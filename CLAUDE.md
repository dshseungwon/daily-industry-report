# CLAUDE.md — The Industry Brief (handoff for Claude Code)

A daily, automated industry-strategy website. A GitHub Actions job runs Claude Code
headless every day, generates GICS industry reports (bilingual EN/KO, self-contained
HTML), commits them, and GitHub Pages serves them. There are also occasional long-form
"special" magazine articles. This file is the context bridge: the code is fully in git,
but the reasoning/decisions from the chat that built this are not — they live here.

Live site: https://dshseungwon.github.io/daily-industry-report/

## Repo layout
- `index.html` — landing page. GENERATED by `build_index.js`; do not hand-edit, rebuild instead.
- `build_index.js` — builds `index.html` from `reports.json`.
- `reports.json` — every report's metadata (one object per report). Fields:
  `{date, gics, sector, set_index, industry_en, industry_ko, global_company,
  korea_company, file, headline_en, headline_ko, accent, special?, format?}`.
- `reports/<YYYY-MM-DD>/*.html` — individual reports, each a self-contained bilingual HTML file.
- `magazine/ai-foundation-models.html` — the special "magazine" article (bright editorial design, bilingual).
- `prompts/daily-industry-report.md` — the exact prompt fed to Claude Code in CI. Edit this to change report generation.
- `rotation.json` — rotation state: `{phase, covered:[gics codes]}`.
- `subindustries.json` — 163 GICS sub-industries (the Phase-2 universe), `[[code,name],...]`.
- `.github/workflows/daily-industry-report.yml` — the daily pipeline.
- `build/game_data.py`, `game_data.json` — separate experiment that extracts game data from reports (non-critical).

## The daily pipeline (.github/workflows/daily-industry-report.yml)
- Schedule: cron `0 21 * * *` (UTC). Job-level `env: TZ: Asia/Seoul` so report DATES are Korea time and match the commit message. (Earlier the date was UTC — that caused a one-day lag and a doubled day; now fixed.)
- Model: `CLAUDE_MODEL: opus`.
- Auth: `CLAUDE_CODE_OAUTH_TOKEN` secret (Max-plan token from `claude setup-token`). It can expire → rotate it if runs silently stop producing reports.
- Steps: checkout → install `@anthropic-ai/claude-code` → `claude -p "$(cat prompts/daily-industry-report.md)" --model opus` → build game_data → "Commit & push" → email digest.
- FAST PATH: the prompt tells Claude to copy the NEWEST existing report as a template and rewrite only the body, so style stays consistent.

## Rotation logic (in prompts/daily-industry-report.md, STEP 1)
- Phase 1 = the 74 GICS Industries (6-digit codes). COMPLETE (full lap done, MECE-verified).
- Phase 2 = the 163 GICS Sub-Industries (8-digit codes). IN PROGRESS. Advances automatically once Phase 1 is fully covered and `subindustries.json` exists.
- Coverage-aware + sector-spread, 7 industries/day. State tracked in `rotation.json`.

## Anatomy of a report (each reports/<date>/*.html)
- Self-contained, NO external dependencies. Mobile-first, card-based.
- Bilingual: every visible text node is `<span class="en">…</span><span class="ko">…</span>`. Toggle adds `lang-ko`/`lang-en` to `<body>`, persists in `localStorage['dis-lang']`. Reports default to English; the landing defaults to Korean.
- Sections: overview → chain (value chain flow + profit-pool bar) → size (vertical column chart, zoomed baseline) → share (two CSS conic-gradient pie charts) → positioning (2x2 inline SVG) → forces (Porter, rated) → reg (latest laws/policy) → ksf → players (Global #1 + Korea #1, each with stat grid incl. market cap, SCQA diagnosis, strategy tracks) → scenarios (bull/base/bear) → footer (real source links).
- GICS taxonomy breadcrumb (`.gics-tax`) in the hero: 3 levels (Sector > Industry Group > Industry) for Phase 1, 4 levels (+ Sub-Industry) for Phase 2. CSS lives in `<style id="gics-tax-css">`.
- Top bar starts with a `.nav-home` gold pill linking to `../../index.html` (back to the landing).
- Profit-pool bar: each value-chain stage shows its INDICATIVE % share of the profit pool (`.pv` reads `~NN%`, shares ~100%, bar width proportional, hi/med/lo only tints color). IMPORTANT: `.pool-row .pfill` MUST include `display:block` — it is a `<span>`, and without it the colored fill is invisible (only the grey track shows). This was a real bug; keep the rule.

## Conventions & decisions (please preserve)
- Korean register (BOTH reports and magazines): natural, readable honorific 존댓말 — base "~습니다/~ㅂ니다" with "~죠/~거든요/~요/~ㄹ까요?" mixed in for rhythm, like a sharp native Korean magazine writer explaining to the reader. NOT stiff report-speak ("~로 파악됩니다"), NOT plain "~다" 문어체, and above all NOT translationese: drop the English skeleton, split/merge sentences, kill 불필요한 피동 and "~에 대해/~에 의해" and 무생물 주어 직역. (Earlier reports used 합쇼체 보고체 and magazines used "~다" 문어체; both were migrated to this natural 존댓말 — see prompts/daily-industry-report.md STEP 3 and the ko-rewrite/ tooling.)
- Section titles are plain and standard (no flowery headlines).
- Every company/lab (incl. Anthropic/Claude) is described evenhandedly and factually — no promotional tilt.
- Special reports are NOT GICS rotation items: their `reports.json` entry has `special:true` (and `format:"magazine"`); `build_index.js` renders them in a dedicated top "Special Reports" section, never under a daily date. Files live under `magazine/`.
- The magazine article ramps easy → deep and ends with a "09 · Consulting" section + glossary. NOTE: that consulting section + the easy→deep KO prose exist in the repo magazine only; a separate ChatGPT book-style Korean translation of ch.1–8 exists only in the user's ChatGPT chat (ch.8 "병목" was captured; ch.1–7 were not exported).

## Common commands
- Rebuild the landing after editing reports.json: `node build_index.js`
- Manually trigger the daily run (REST): POST to `…/actions/workflows/daily-industry-report.yml/dispatches` with `{"ref":"main"}` (or `gh workflow run daily-industry-report.yml`).
- MECE sanity for a lap: every GICS code appears exactly once, code↔name consistent, and the filename's code matches `gics`.

## Known issues / things to watch
- The CI "Commit & push" step does a plain `git push` (no rebase). If you push to `main` while a daily run is mid-flight, the run's final push fails and that day's batch is lost. Don't push during an active run, or be ready to re-dispatch.
- GitHub-hosted runners occasionally cancel the job ("runner received a shutdown signal"); that day may be missing — just re-dispatch. (Gaps have happened on busy days.)
- `CLAUDE_CODE_OAUTH_TOKEN` can expire; symptom is a "successful" run that commits nothing.
- The landing "Up next" preview still derives from the 74-industry (Phase-1) lane logic, so it's slightly stale now that we're in Phase 2 sub-industries — fine to leave or update.
